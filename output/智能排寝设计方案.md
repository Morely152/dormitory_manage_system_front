# 高校智能排寝系统设计方案（确定性贪心 + 代价评价 + 局部交换）

## 一、总体架构

系统采用 **预分配模拟 → 确定性贪心分配 → 代价评价与局部交换优化** 三阶段流水线。核心目标为：在满足所有硬约束的前提下，自动推算最优插空比并完成分配，再通过轻量级局部交换提升学院集中度，同时全程提供可解释的决策依据与诊断信息。

---

## 二、数据模型

### 2.1 宿舍房间

- 静态属性：唯一标识、楼栋标识、苑区（北/南/西）、绑定性别、总容量、是否研究生宿舍、研究生全空锁定标记。
- 动态属性：已占用床位数、入住老生学院列表、入住新生学院列表（由分配过程维护）。
- 派生状态：是否全空（已占用=0）、是否可插空（0<已占用<总容量且未被锁定）。

### 2.2 待分配学生

- 属性：唯一标识、所属学院、性别、分配状态（未分配/已分配）、分配房间标识。

### 2.3 学院兼容矩阵

- 手动配置的映射表，每个学院对应一组可混住学院，同学院默认自兼容。

### 2.4 距离圈层定义

- **同楼栋**：目标房间与该学院已分配的任一房间属于同一楼栋。
- **同苑区**：同苑区但不同楼栋。
- **跨苑区**：不同苑区。

---

## 三、用户可配置参数

| 参数                   | 说明                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| **最大插空比**         | 每个学院插空人数占比的上限，全局统一设置。                                                                  |
| **指定苑区优先**       | 按学院+性别选择目标苑区。指定后先从该苑区全空房分配，容量不足再放宽到其他苑区；未指定时按房间容量与当前剩余人数的接近度选择。 |
| **研究生宿舍后备开关** | 控制是否在普通资源耗尽后启用研究生宿舍。                                                                    |
| **交换优化开关**       | 控制是否在分配完成后执行局部交换优化。                                                                      |
| **代价权重**           | 苑区分散度、跨区人数等指标的调节权重，可调整优化倾向。                                                      |

---

## 四、预分配模拟与插空比推算

### 4.1 目标

系统自动寻找能使所有学生完成分配的最小插空比（称为 **必要插空比**），并判断其是否超出用户设定的最大插空比。

### 4.2 流程

1. 对原始数据进行深拷贝，获得独立的模拟环境。
2. 在 $[0, 最大插空比]$ 区间内执行二分搜索，每次使用完整的确定性贪心分配流程（不含交换优化），检查能否全部安置。
3. 记录每次失败时的详细原因，分类统计未安置学生数量及床位缺口类型。
4. 若找到的必要插空比 ≤ 最大插空比，则将此值作为正式分配的插空比上限；否则拒绝执行分配，向用户提供诊断报告。

### 4.3 诊断报告

包含：

- 必须将最大插空比至少提升到的具体数值。
- 资源瓶颈明细：按学院、性别列出未安置人数及原因类别（全空床位不足、同学院插空不足、兼容插空不足、已达插空比上限等）。
- 资源快照：各苑区剩余全空床位、同学院插空床位、兼容插空床位数量。
- 调整建议：提高插空比、释放特定苑区房间、修改兼容关系或手动指定北区优先。

---

## 五、确定性贪心分配（核心引擎）

### 5.1 阶段一：全空寝室优先分配

#### 5.1.1 分组与排序

- 将未分配学生按学院、性别分组，统计每组人数。
- 排序规则：
  1. 存在容量完美匹配的全空房间的组优先。
  2. 其余组按人数从大到小排列。

#### 5.1.2 房间选择策略

对每个分组，依据该学院+性别的**指定苑区**决定苑区搜索顺序：

- **若指定苑区**
  先筛选指定苑区的可用全空房，优先匹配完美容量房间，次选剩余床位与当前剩余人数最接近的房间；指定苑区容量不足时再搜索其他苑区。

- **若未指定苑区**
  所有苑区处于同一优先级，不按北/南/西名称增加惩罚；直接按 `abs(房间剩余床位 - 当前批次剩余人数)` 升序，再按剩余床位数和房间自然序打破平局。

#### 5.1.3 房间分配与拆分

- 优先选取容量恰好等于剩余人数的房间，整间分配。
- 否则选取剩余容量最接近的房间，将尽可能多的学生分配进去，剩余人数继续循环分配。
- 每完成一个房间的分配，更新房间占用信息和该学院全空床位苑区分布记录。

#### 5.1.4 溢出处理

- 无法在全空阶段完全安置的学生自动流入插空阶段。

### 5.2 阶段二：插空贪心分配

#### 5.2.1 可用插空房间池

- 筛选条件：房间已有人入住但未满、性别匹配、非研究生全空锁定（若为研究生房间且`occupied==0`且锁定则不可用）。

#### 5.2.2 距离圈层构建

- 系统维护每个学院**已占领的楼栋列表**（随分配动态更新）。
- 对于待分配学生：
  - 圈层1：已占领楼栋中的插空房间。
  - 圈层2：同苑区且非已占领楼栋中的房间。
  - 圈层3：其他苑区的房间。
  - 若学院尚无已占领楼栋，跳过圈层1，从圈层2开始，并在同苑区内优先选择该学院老生所在楼栋。

#### 5.2.3 圈层内子优先级

每个圈层内按以下顺序搜索：

1. 同学院：房间内老生学院包含该学生学院。
2. 兼容学院：房间内老生学院与该学生学院存在兼容关系。
3. 若同一子优先级有多个候选，优先选择空余床位最少的房间（促使尽快填满），若仍并列则选距离已占领楼栋更近的房间。

#### 5.2.4 插空比控制

- 每个学院的插空人数上限 = 该学院新生总数 × 当前采用的插空比（由预分配模拟确定）。
- 每次成功插空后增加计数，一旦达到上限，该学院后续新生跳过插空阶段，进入失败池。

### 5.3 阶段三：研究生宿舍后备

- 仅当前两阶段均无法安置的学生才尝试研究生宿舍。
- 要求：标记为研究生宿舍，性别匹配，未满，且若为全空房间则锁定标记必须为`false`。
- 分配时仍遵循同学院优先、兼容次之，不做距离圈层区分。
- 仍失败的学生记录为最终未安置。

## 六、代价评价与局部交换优化

### 6.1 代价函数

量化分配方案的“集中度体验”，可由权重调节：

| 指标       | 计算方式                                   | 典型权重       |
| ---------- | ------------------------------------------ | -------------- |
| 苑区分散度 | 每个学院新生分布的苑区数，每多一个苑区加罚 | 高             |
| 跨区人数   | 跨苑区安置的学生总数                       | 中             |
| 楼栋分散度 | 每个学院新生分布的楼栋数，每多一栋楼加罚   | 低             |
| 全空碎片   | 全空房间被拆分后剩余的零散空床位数         | 极低（可忽略） |

总代价为各项加权和，数值越低越好。

### 6.2 交换约束

仅允许满足以下全部条件的两名同性别学生进行房间交换：

- **性别一致**：两人同性别，保证与房间绑定性别匹配。
- **房间不同**：且所在房间均未被管理员手动锁定。
- **兼容性检查**：交换后，新入住者学院与目标房间内所有其他成员（老生+剩余新生）学院两两兼容。
- **北区全空约束**：若开启均衡保护，交换后不得导致任何学院的全空床位全部集中在北区。
- **插空比约束**：交换后，双方学院插空人数均不得超过其上限。
- **研究生锁定**：若涉及研究生全空锁定房间，不得将新生换入处于锁定状态的空房间。

### 6.3 优化搜索策略

采用**随机爬山法**：

1. 构建候选学生池（可聚焦于当前处于跨区状态的学生）。
2. 迭代进行：随机选取一名候选学生 A 和任意同性别不同房间的学生 B。
3. 若 A、B 满足交换约束，计算交换前后的代价变化（增量计算，仅影响相关学院指标）。
4. 若代价降低，执行交换并更新房间状态、学院苑区/楼栋分布记录；否则放弃。
5. 设置最大尝试次数（如 5000 次）和连续无改善次数上限，控制计算量。

### 6.4 用户交互

- 分配完成后展示代价仪表盘，可一键触发优化。
- 优化过程异步执行（如 Web Worker），完成后展示改善幅度与交换日志。
- 支持一键回退至原始方案，可对特定房间/学生加锁禁止参与交换。

## 七、整体执行流程

1. **数据加载与校验**：导入或编辑房间、学生、老生信息、兼容矩阵；校验数据完整性，标记异常。
2. **参数配置**：设定最大插空比、学院+性别指定苑区、研究生后备开关、优化开关及代价权重。
3. **预分配模拟**：二分搜索必要插空比。
   - 若可行，采用必要插空比进入正式分配；
   - 若不可行，展示诊断面板，等待用户调整参数。
4. **正式分配**：执行三阶段确定性贪心分配，生成合法方案。
5. **代价评价与优化**：计算方案代价，根据用户选择执行局部交换优化。
6. **结果展示与微调**：可视化房间占用、学院分布、代价评分；支持手动拖拽微调（实时约束校验）。
7. **方案保存与导出**：可保存当前方案快照，导出分配明细表。

---

## 八、容错与边界处理

- **数据缺失或冲突**：如房间已占人数超过容量，则前端校验拦截，不予参与分配。
- **全男生/全女生场景**：楼栋性别限制自动过滤，不会产生性别混住错误。
- **兼容关系缺失**：未配置兼容的学院之间禁止插空/交换。
- **指定苑区容量不足**：指定苑区床位不足时，系统保留指定苑区优先级，随后自动流向其他苑区；未指定苑区时始终按容量接近度规则选择。
- **研究生宿舍资源不足**：最终未安置的学生将在结果中明确列出，并提供床位缺口分析。

---

本方案以确定性贪心保证分配成功率与速度，以预分配模拟实现参数自调优，以轻量级局部交换优化提升居住体验，全程逻辑透明、可解释，适合纯前端实现，能够满足高校宿舍智能化分配的实际需求。
